# v5.3.0 — Disk footprint, MAESTRO robustness, and new transport interfaces

This release makes long MAESTRO chains cheap to store and harder to break. Finished cases now occupy a fraction of their former footprint (lean PORTALS pickles, a `mitim_prune_maestro` cleanup tool, `derived`-free powerstates, and a fixed TRANSP CDF descriptor leak that was pinning multi-GB files on scratch), and a set of new TRANSP/EPED knobs — sawtooth-period floor, boundary-surface backoff, extraction-slice control, q-seed sanitization, configurable 99.5% shaping — addresses failure modes seen on compact, strongly shaped devices. On the physics side it adds a QuaLiKiz interface usable as a PORTALS turbulence backend, a real plasma composition for EPED, local-optima mining in the Bayesian-optimization loop, and a pulse-duration (volt-second) calculator.

### New Features

*   💾 **MAESTRO disk footprint — lean PORTALS pickles**: under `keep_all_files: false`, PORTALS beats persist a *lean* `optimization_object.pkl` that drops the fitted GP surrogates (≈⅔ of each file), and only the **last** PORTALS beat keeps its heavy outputs — chaining only needs `surrogate_data.csv` and each beat's `input.gacode`. The per-iteration checkpoints written *during* the run stay full, so a preempted run still resumes. Together this roughly halves a finished case (e.g. ~210 → ~100 MB). Replotting metrics is unchanged (only the GP-posterior "Expected" plots are unavailable). New low-level switch `MITIM_BO.save(lean=True)`; standalone PORTALS runs and `keep_all_files: true` are unaffected.

*   🧹 **`mitim_prune_maestro`**: applies the `keep_all_files: false` space savings to a run that already **finished** with `keep_all_files: true` — wipes each beat's `run_<name>/` folder (the multi-GB TRANSP CDF included) and slims/prunes the PORTALS beat outputs, leaving `beat_results/` and the `initializer_*` folders untouched. Dry-run by default (reports bytes freed); `--apply` to delete. Reclaims most of a finished case (e.g. ~950 → ~200 MB) while keeping everything needed to replot and chain.

*   💾 **PORTALS `optimization_extra.pkl` — recomputable `derived` dropped**: the per-iteration powerstates no longer carry each profile's full `derived` dict (flux-surface geometry, gradients, …). It is stripped before pickling and rebuilt lazily on read in `PORTALSanalysis`, cutting the file by ~60% (e.g. ~104 → ~40 MB). Base profiles and transport fluxes (not recomputable) are kept at full float64. Gated by `store_lean_powerstates` (default `True`).

*   🌀 **QuaLiKiz interface**: new `mitim_tools.qualikiz_tools` (`QLKtools.QuaLiKiz`) runs and reads QuaLiKiz standalone from an `input.gacode`, and is selectable as a PORTALS turbulence backend with `transport.evaluator_instance_attributes.turbulence_model: "qlk"` (the neoclassical side is independent and keeps NEO). All radii — and every gradient-perturbation case used for flux uncertainties — are packed into a *single* execution via QuaLiKiz's own `dimx` scan, so it stays one job per PORTALS iteration. Requires the external `qualikiz_tools` package and a `qualikiz` entry in `config_user.json`; the import is caught, so workflows are unaffected when it is absent. **NOTE: QuaLiKiz uses circular / s-alpha-like geometry — shaping is dropped in the `gacode_state.to_qualikiz` mapping, so fluxes are not directly comparable to TGLF on a strongly shaped plasma — and provides no turbulent electron-ion exchange Qie (zero-filled, so `turbulent_exchange_as_surrogate` must stay `False`). Both are properties of QuaLiKiz itself, not of this interface.** Teaching scripts: `qualikiz_01_run_from_inputgacode.py` and `portals_03_qualikiz_standard.py`.

*   ⚛️ **EPED plasma composition (full EPED)**: the MAESTRO EPED beat and `EPEDtools.EPED.run` now feed EPED the actual main-ion mass and an effective impurity derived from the state (reproducing both Zeff and fuel dilution, `zi_eff = (Zeff − d)/(1 − d)`) instead of a hardcoded 50/50 D-T + neon. `m`/`z`/`mi`/`zi` default to the old values and are overridable via the beat's `corrections_set`; a new `zeff_location` knob (`vol_avg` default, `pedestal`) sets where Zeff and the dilution are taken; the EPED-NN path is unaffected. **NOTE: in EPED1 the only composition quantity that enters the solve is `Zeff` (via TOQ / bootstrap collisionality) — the mass/charge entries are recorded but inert.**

*   ⛏️ **Local optima mining in Bayesian optimization** (`local_optima_options`): after every `n_acq_batches_per_cycle` acquisition batches, the BO loop can mine the GP surrogate for diverse local optima using independent L-BFGS-B gradient-ascent restarts, evaluate those points with the physics model, and inject them into the training data. `apply: false` by default (existing runs behave identically); restart counts, diversity-selection algorithm and trigger conditions are configurable. Points are labeled by source in `optimization_data.csv` (`training`, `acquisition`, `local_optima`).

*   🪚 **MAESTRO TRANSP adaptive sawtooth-period floor** (`min_sawtooth_period_ms`): on compact, cold-core plasmas the Park-Monticello period `tau_PM ~ R^2 * Te0^1.5 / Zeff` — which floors the Porcelli trigger's crash interval — is sub-ms, so sawteeth crash every ~1 ms, forcing sub-ms timesteps and a multi-GB output CDF. The TRANSP beat now sets `c_sawtooth(2) = min_sawtooth_period_ms / tau_PM` per case (`tau_PM` from the new `PLASMAtools.park_monticello_sawtooth_period`), imposing an absolute floor on the crash interval while leaving large machines untouched. Default **10 ms** in the maestro template; `null` bypasses.

*   🧩 **MAESTRO TRANSP boundary-surface backoff** (`plasma.parameters.separatrix.boundary_surface_psin`): the fixed TRANSP boundary can now be extracted at a flux surface just inside the separatrix (e.g. `0.995`) rather than at it — a sharp / near-X-point separatrix can trip TRANSP's boundary curvature-ratio abort, and a surface a hair inside is rounder while preserving the true plasma shape (unlike lowering `n_mxh`). Default `1.0` = separatrix (unchanged). **This knob and `n_mxh` are now consumed by the FIRST TRANSP beat only: it builds the boundary curve, freezes it, and every later beat reuses it verbatim. Re-deriving it per beat compounded — TRANSP is fixed-boundary, so its output psiN=1 surface IS the boundary it was given — silently shrinking the plasma ≈1.3% in minor radius over 4 TRANSP beats.** Works best with `separatrix.internal_flux_file`, which supplies a real equilibrium's radial shaping decay so interior surfaces are physically rounder; that path now also carries the file's poloidal-flux mapping through the initializer's FREEGS profile-correction step.

*   🧊 **MAESTRO 99.5% shaping re-freeze timing** (`maestro.refreeze_995_after_beat`): controls WHEN the pedestal shaping fed to EPED is fixed, orthogonal to `separatrix.freeze_995_from` (which sets HOW it is extracted). `0` (default, old behavior) freezes at initialization; `N>0` re-extracts once from beat N's evolved equilibrium and reuses it thereafter; `null` never freezes, so each EPED beat recomputes from its own current equilibrium. Motivated by separatrix-initialized runs, whose init 99.5% values are a parametric guess rather than a solved equilibrium. Also warns at runtime that `freeze_995_from`'s parameterization only applies to geqdsk init.

*   🎯 **MAESTRO configurable 99.5% shaping surface** (`plasma.parameters.separatrix.shaping_extraction_psin`): the psiN surface at which the pedestal shaping (kappa995/delta995/zeta995, s_three995/s_four995) is sampled is now a knob, orthogonal to `freeze_995_from` (HOW) and `refreeze_995_after_beat` (WHEN). Default `0.995` reproduces current behavior bit-for-bit and the dict keys stay named "995"; raising it toward the separatrix (e.g. `0.998`) yields higher kappa/delta. Threaded to both extraction paths (the geqdsk flux-surface tracer and the profile interpolation), so every init mode and re-extraction honors it.

*   🎚️ **MAESTRO TRANSP extraction-slice selector** (`extract_at`): which CDF time slice is handed to the next beat is now configurable in the transp beat's `parameters_prepare` — `saw` / `saw-N` (the last sawtooth, or N coarse slices before it) or `last` / `last-N`. Default `saw-1` reproduces the historical behavior (a small step-back that avoids sampling the crash profiles on the coarse MAESTRO grid).

*   🩹 **MAESTRO TRANSP q-seed sanitization** (`sanitize_q_input`): an over-peaked equilibrium seed (very low on-axis q0 → q=1 surface far toward the boundary) can make TRANSP's Kadomtsev sawtooth model hard-exit on its first crash, before current diffusion relaxes q. If set (e.g. `0.95`), the initial q-profile seed is rescaled so q0 hits that value, anchored on q95 (edge/shape preserved); current diffusion then relaxes q over the flattop. Applied to the TRANSP seed only; `null` (default) is a no-op.

*   ⚖️ **MAESTRO Lengyel beat Zeff relaxation** (`zeff_relaxation_factor`): the beat's core-Zeff update can now be damped toward the state it received instead of jumping to whatever the divertor needs in one shot. `[0,1]`, default `1.0` = old unrelaxed behavior; the blended Zeff profile is then re-solved for the seed-impurity density that reproduces it. Operates at the aggregate Zeff level rather than matching species identity, so it behaves the same on the first Lengyel beat as on later ones.

*   ⏱️ **Pulse-duration (max flattop time) calculator** (`plasmastate_tools.utils.calc_pulse_duration.calc_flattop_time`): estimates the maximum achievable flattop duration of a `gacode_state` from a central-solenoid volt-second balance, chaining `cfspopcon`'s inductance, resistivity and flux-consumption algorithms off the state's geometry, peaking, Zeff and dilution, and printing the full breakdown (internal/external/resistive flux, poloidal field flux, Spitzer/neoclassical resistivity, loop voltage, flux available vs. needed). The available CS flux can be supplied directly (`overwrite_flux`) or derived from `cs_change_in_field` + `inboard_to_CS_distance`, both unit-checked. New teaching script: `pulse_duration_01.py`.

*   🔌 **`gacode_state.recompute_targets()`**: re-derives the radiation (qbrem/qsync/qline), fusion alpha-heating (qfuse/qfusi) and electron-ion exchange (qei) profiles from the kinetic profiles with the analytic target model, on the full radial grid (no edge points left stale). It is now the single entry point used by the MAESTRO confinement beat and RAPIDS instead of their inline powerstate round-trips; `debug=True` plots each recomputed channel against the profiles that drive it.

*   📊 **MAESTRO summary plots**: `Outputs/maestro_summary.md` now embeds the per-beat "special quantities" evolution and the timing breakdown (`maestro_special.png`, `maestro_timing.png`) next to the beat-flow diagram, and `mitim_plot_maestro --summary` (alias `--special`) plots only those two cross-beat tabs, skipping the per-beat / profile / transition tabs — a fast at-a-glance view of a run.

*   🧭 **`mitim_plot_neo`**: reads and plots NEO results from an existing folder, mirroring `mitim_plot_tglf` (positional folders, `--suffixes`, `--gacode` for normalizations) via a new `NEO.prep_from_file`.

*   ⚙️ **SR acquisition optimizer `halt_on`** (`best` | `all`): the batched restarts halt together when the *best* restart meets the tolerance (`best`, default, unchanged) or only once *every* restart does (`all`) — use `all` when more than one `x_best` is consumed, so all returned candidates are comparably converged. The batched-restart behavior of ROOT and SR is now documented in `namelist.optimization.yaml`.

### Bug Fixes

*   🐛 **TRANSP CDF file-descriptor leak (major MAESTRO scratch regression)**: the multi-GB TRANSP output CDF was held open for the **entire** MAESTRO run and fork-inherited by every later PORTALS/TGLF worker, so once the run folder was wiped (`keep_all_files: false`) the deleted CDF stayed pinned on disk as an NFS silly-rename (`.nfsXXXX`) until the case ended — inflating each case's scratch use by 2–5 GB and overrunning per-user quotas on large scans. The TRANSP beat now releases the cached `transp_output` at the end of `run()`, before the PORTALS beats fork; `transp_output` gained an idempotent `close()`, and the metadata/finalize readers close their handles.

*   🐛 **TRANSP run-abort detection & CDF-build retry**: a TRANSP run that aborts during initialization (e.g. a t=0 TEQ equilibrium failure) is now flagged `stopped` instead of `finished` — a fatal `ABORTR`/`bad_exit`/segfault in the log outranks the singularity wrapper's unconditional "Finished TRANSP run app." line — so the run fails fast with the real error. When the finish step fails to build `{runid}.CDF` for a *completed* run, `TRANSPsingularity.fetch` falls back to a `look` rebuild instead of hard-failing, and mid-run intermediate grabs are now best-effort (logged and skipped rather than killing a healthy run).

*   🩺 **Informative TRANSP failure message** (`TRANSPdebug`): a stopped TRANSP run now raises with a *best-effort estimate* of the cause parsed from the run log — the signal and a plain-language gloss, the simulation time/step, and the physics event at the trap (MHD equilibrium/TEQ vs Porcelli sawtooth) — instead of a bare "TRANSP stopped". Controlled Fortran aborts (`ERRSET`/`%bad_exit`, which print no signal line) are parsed too, naming the real cause on the `??<reason>` line (e.g. "curvature ratio too small" during the PRGCHK boundary check). InfiniBand/RDMA container-launch failures are flagged as infrastructure rather than physics. The message is a heuristic reading of the log, **not** a guaranteed root cause. Usable interactively via `diagnose_transp_logfile`.

*   🐛 **MAESTRO TRANSP Porcelli sawtooth triggering**: earlier MAESTRO runs could finish without ever triggering sawteeth if the Park-Monticello predicted period was too long (only 10% of it was taken as the minimum). The TRANSP beat now accepts a user-specified sawtooth-period floor (see the new feature above).

*   🐛 **MAESTRO TRANSP early-extraction floor** (`min_extraction_flattop_fraction`, default 0.5): a plasma whose only sawtooth fired early (then never again) had its profiles extracted before heating / current diffusion settled. The extraction is now floored at this fraction of the flattop window; healthy runs (last sawtooth already past mid-flattop) are unchanged, and `null` disables.

*   🐛 **geqdsk → `input.gacode` `B_unit`** (`MITIMgeqdsk.to_profiles`): `torfluxa` was divided by an extra `2π` — megpy's `derived['phi']` is already per-radian — so `B_unit`, and with it the gyroBohm normalization and `P_PRIME_LOC`/`BETAE` (`∝ 1/B_unit²`), came out `2π` too small in any `input.gacode` built through `to_profiles`. **In practice this affects almost nobody**: standard `input.gacode` come from `profiles_gen`/TRANSP and MAESTRO's main equilibrium path calls `equilibrium_to_profiles`, both unaffected. It only bites when a `to_profiles` output is fed *directly* into a transport code.

*   🐛 **MAESTRO Lengyel beat edge-temperature bump**: when the Lengyel separatrix temperature far exceeded the incoming one (factor ~2 or more), the `rhotop`→separatrix rescaling lifted the mid-pedestal above the pedestal top, leaving a spurious local Te/Ti maximum (e.g. a 7.7 keV bump on a 5 keV pedestal top). The blend is now an additive quadratic offset bounded by the separatrix change, so the edge never rises above its top; the `rhotop is None` fallback likewise shifts by a constant offset instead of rescaling the whole profile.

*   🐛 **MAESTRO EPED cold-start on preemption+requeue** (`forceifcold_start`): a preempted MAESTRO job that auto-requeued mid-beat re-cold-started EPED, found the leftover `output_run1.nc` from the killed attempt, and hit an interactive "rerun from scratch?" prompt that raised `InteractiveTerminalError` in a batch job — misreported upstream as "EPED failed to run". A cold-start that finds an existing output now warns and reruns from scratch. `eped_beat.prepare` defaults it to `True`; standalone `EPEDtools.EPED.run` keeps the interactive prompt.

*   🐛 **PORTALS restart robustness**: a resumed optimization whose pkl checkpoint lagged behind `optimization_data.csv` could leave `x_next` empty and crash the results writer with an `IndexError`. `MITIM_BO.updateSet` now treats an empty `x_next` as a no-op and skips the step.

*   🐛 **PORTALS on GPU**: a few numpy operations were being applied to PyTorch CUDA tensors (silently fine on CPU, raising on GPU) — the `yminymax_atleast` bounds in `PORTALSinit` now use `torch.minimum`/`torch.maximum`, and `improve_resolution_profiles` coerces a CUDA `rhoMODEL` to numpy first. Separately, `print_machine_info` no longer crashes on newer PyTorch (`props.total_mem` → `total_memory`). **NOTE: not an exhaustive sweep — other numpy-on-CUDA-tensor instances may remain.**

*   🐛 **`mitim_job.run()` retry robustness**: the "repeat once after a transient error" retry re-ran the in-place path relativization on already-relative paths and crashed in `relative_to()` with a misleading `'mitim_bash.src' is not in the subpath…` error; `run()` is now idempotent w.r.t. its input file/folder lists and surfaces the real failure.

*   🐛 **MAESTRO per-beat logs** (`Outputs/Logs/beat_<n>_*.log`) are now line-buffered, so a long-running beat's log streams progress live instead of staying empty until the beat finishes.

*   🐛 **MAESTRO engineering scans** (`launch_scan`): the `exclude` and `qos` SLURM allocation settings were silently dropped and are now forwarded to the array submission.

*   🐛 **`mitim_check_maestro`** now recognizes the sharpness, confinement and lengyel beats (previously shown as `UNKNOWN`).

*   🐛 **TRANSP (singularity) finish** no longer leaves a duplicate copy of the retrieved `results/` tree (notably the heavy `.CDF`): its contents are surfaced into the run folder and the redundant copy removed.

*   🐛 **`mitim_plot_transp` boundary-less g-file**: a TRANSP run whose reference g-eqdsk has no plasma-boundary contour (`nbbbs=0`) no longer crashes the read — `getGFILE` warns, skips it and falls through to the next candidate extension.

*   🐛 **`mitim_plot_cgyro` timing panels** no longer clip later cases: the y-axes now expand to fit every overlaid case (`set_ylim(bottom=0)` was disabling y-autoscale).

*   🐛 **`initialization_simple_relax` folder copy** now preserves symlinks, so a transport folder containing one (e.g. a QuaLiKiz run folder) no longer breaks the copy.

### Changes for developers (internal execution)

*   🤖 **MAESTRO investigation subagent** (`.claude/agents/maestro.md`): a Claude Code agent that forensically compares and debugs MAESTRO runs — it knows the `Beats/` layout, each beat's inputs/outputs, where the logs/timing/namelist artifacts live, and how to load and overlay states headlessly. Shipped in-repo by un-ignoring `.claude/agents/` (the rest of `.claude/` stays local).

*   🔎 **MAESTRO EPED beat failure diagnostics**: reports the EPED inputs (R, a, BetaN, …) alongside the "no stable solution" warning and the final failure, and now distinguishes a compute-node execution failure (TOQ/ELITE produced no output files) from a genuine pedestal no-solution — the former is surfaced immediately instead of being masked by futile teped-lowering retries.

*   🔎 **MAESTRO scan per-case logs** now symlink each case's `slurm.out`/`slurm.err` to the live SLURM array logs instead of redirecting, so logs stream live and are reachable from both the case and main folders.

*   🔧 **SLURM `exclusive` accepts a string**: `exclusive: "user"` (or `"mcs"`) now emits `#SBATCH --exclusive=user`, so a scan can keep nodes free of *other* users while still packing its own array tasks onto each node. A bare `True` is unchanged. MAESTRO scan arrays now forward `slurm['exclusive']` (it was hardcoded off).

*   🧮 **E×B / parallel-velocity shear as state quantities**: `mitim_state.derive_quantities` now exposes `derived['gamma_exb']` and `derived['gamma_p']` — the E×B and parallel-velocity shearing rates in TGLF's `VEXB_SHEAR`/`VPAR_SHEAR` normalization (`c_s/a`), computed once from `w0`, `q`, `r`, `a`, `c_s`. `to_tglf` now consumes them instead of recomputing the formula inline (behavior-preserving), so the shearing-rate profile is available on any state without a TGLF prep. Alongside, `NEO.plot_vgen` (and `mitim_plot_vgen`) gained an optional `mark_rho` to scatter chosen radii on the smoothed profiles.

### Back-compatibility considerations and defaults

*   💾 **Lean PORTALS pickles under `keep_all_files: false`**: intermediate PORTALS beats' `optimization_object.pkl`/`optimization_extra.pkl` are pruned, and the retained (last-beat) `optimization_object.pkl` is lean. Replotting metrics still works; the GP-posterior ("Expected") plots and a pickle-based surrogate resume of those finished beats are not available. Set `keep_all_files: true` to retain full pickles.

*   🪚 **Sawtooth floor defaults**: `min_sawtooth_period_ms` defaults to **1 ms** in `TRANSPbeat.prepare`, so namelists without the key reproduce the historical behavior; the maestro **template** sets **10 ms**. `null` bypasses the adaptive floor.

*   🧊 **MAESTRO `freeze_995_from` default → `analytic`**: the maestro template now extracts the 99.5% pedestal shaping by tracing the actual psiN=0.995 flux surface and fitting the Miller-analytic shape to it, instead of `analytic_interpolation` (interpolating the per-surface Miller-coefficient profiles to psiN=0.995). Both target the same surface; the traced fit is the more direct measure. Set `freeze_995_from: analytic_interpolation` to restore the old default.

*   🔮 **PORTALS capability tests renamed** to name their turbulence model: `portals_01_standard.py` → `portals_01_tglf_standard.py` and `portals_02_multichannel_turbulent_exchange.py` → `portals_02_tglf_multichannel_turbulent_exchange.py`, joined by the new `portals_03_qualikiz_standard.py`. Only the teaching scripts moved (no API change), but bookmarks/doc links to the old paths need updating.
